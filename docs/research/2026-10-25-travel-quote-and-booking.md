# Travel quote and booking: offline-first estimator on open data (checked 2026-10-25)

## 1) Question and constraints
How should the platform price "treatment + round-trip flight (+ hotel nights)" from the patient's city to the clinic's city and let the user book appointment and tickets? OWNER HARD CONSTRAINT: no paid services at all; the repo runs fully offline with no API keys by default; free sign-up APIs may exist only as optional adapters; default = offline estimator on open data. Also: deterministic public demo, no card, no real bookings, reproducible, country-agnostic (fictional clinics in real cities), EN+RU UI, Python or TS. Research used all caps (8+4 searches, 6+3 fetches). Failed fetches: Amadeus portal (empty), Travelpayouts docs (403), OpenFlights data page (404), BTS DB1B page (403); those rows rest on search snippets (Q in section 6). Unchecked items are marked UNVERIFIED; terms on caching or displaying fares were verified for no provider.

## 3) Recommendation
BUILD the estimator, slot engine and fake payments; REUSE open data (OurAirports; OpenFlights only as a hint; DB1B and Kaggle only to fit parameters, committing coefficients not rows); ADAPT keyed services into optional adapters behind the same ports (Fare, Order, Lodging, Payment, Slot, Fx, Geo): FareProvider.quote(origin_iata, dest_iata, depart, return, pax) -> FareQuote{low, mid, high, currency, source: estimate/sandbox/cached, as_of, model_version}, default adapter offline with a fixed as_of.
Why: with no paid services and no keys only an open-data model is deterministic, free and reproducible; real fares scatter about 25-40% even around a perfect route average, so the honest product is a calibrated range with a published error, not a quote; no live source can be the default (Amadeus gone, Kiwi closed, Duffel test prices fake, Travelpayouts cached).
Labels: ESTIMATE chip on flight, hotel, FX-converted figures and any total containing them, with range and basis line; SAMPLE on fictional clinic prices; SIMULATED on demo orders; details in section 4.

## 4) Improvements worth trying
- Calibrate offline and publish the error: fit on DB1B (distance taper, quarterly season) and Kaggle (advance purchase), hold out whole routes, report median absolute % error in the README and a UI tooltip, set the range from residual quantiles (20th to 80th percentile); commit params.json with dataset versions.
- Label spec: every money figure has a source chip (ESTIMATE amber, SAMPLE, SIMULATED, SANDBOX, CACHED + as-of); estimates show a range and one basis line ("typical economy round trip, booked 30-60 days ahead, taxes assumed, model v1, median error x%"); a total with any estimate is "Estimated total"; FX says "pinned rate of <date>"; footer "excludes bags, seats, visas, insurance; not a fare quote; demo, no real booking or payment"; treatment price says "pre-consultation estimate, final plan after examination"; no "Book now" on an estimate, the button reads "Reserve (demo)"; chip text translated EN+RU.
- Check international scale with the optional Travelpayouts token on about 100 route-date pairs, store only error metrics, add region multipliers if the bias is systematic.
- Precompute quotes for fictional clinic x patient city x month into JSON so GitHub Pages can serve the demo with no backend; the live estimator stays for local runs.
- Adapter contract tests (deterministic, symmetric, monotone in distance, low <= mid <= high), cassettes for optional adapters; offline map = great-circle arc over bundled Natural Earth land in MapLibre without tiles (UNVERIFIED).
